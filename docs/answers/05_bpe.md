# Step 05 확인 문제 해설

[← 본문](../05_bpe.md)

## 1. Pre-tokenization이 없으면? 공백을 앞에 붙이는 이유는?

pre-tokenization 없이 전체 텍스트에서 pair를 세면 빈도 높은 단어 경계 조합이 병합된다: `"e "`, `" t"`, `"the "`, `". "`, `"dog."`, `"of the"` 등. 결과적으로

- 같은 단어가 주변 문자에 따라 다르게 분할된다(`"dog"`, `"dog."`, `"dog,"`가 각각 다른 토큰 열).
- 단어+구두점 조합이 어휘를 차지해 어휘 효율이 떨어진다.

공백을 단어 **앞**에 붙이면(`" dog"`) 문장 중간의 같은 단어는 항상 같은 토큰이 되고, 디코딩 시 별도 표식 없이 공백을 복원할 수 있다. 단, 텍스트 맨 앞이나 줄바꿈 직후 단어는 공백 없는 `"dog"`가 되어 다른 토큰이 된다. SentencePiece는 공백을 `▁` 기호로 바꿔 같은 문제를 다룬다.

## 2. 숫자 병합과 산술

BPE는 빈도에 따라 `"2023"`, `"12"`, `"345"` 같은 숫자 조각을 병합하므로 같은 수가 문맥에 따라 다르게 분할되고, 자릿값 정렬이 토큰 경계와 맞지 않는다. 모델은 수천 개의 숫자 토큰 각각의 의미와 덧셈 규칙을 따로 학습해야 하며, 자리올림을 토큰 경계 너머로 처리하기 어렵다. LLaMA는 숫자를 한 자리씩 분할하고, GPT-4 계열 토크나이저는 최대 3자리씩 묶는다. 3자리 묶음을 오른쪽부터 맞추면(천 단위 정렬) 산술 정확도가 오른다는 보고가 있다(Singh & Strouse 2024, "Tokenization counts").

## 3. BPE vs Unigram LM (SentencePiece)

| | BPE | Unigram LM (Kudo 2018) |
|---|---|---|
| 학습 방향 | 바이트에서 시작해 병합(bottom-up) | 큰 후보 어휘에서 시작해 제거(top-down) |
| 기준 | 인접 pair 빈도 | unigram 언어모델 우도. EM으로 각 조각 확률을 추정하고, 제거 시 우도 감소가 가장 작은 조각부터 제거 |
| 인코딩 | merge 규칙을 rank 순으로 결정적으로 적용 | 조각 확률의 곱이 최대인 분할(Viterbi). 확률적 분할 샘플링 가능(subword regularization) |

Unigram은 분할을 확률 모델로 다루므로 여러 분할을 샘플링해 학습 데이터 증강에 쓸 수 있다. BPE는 학습·인코딩이 단순하고 결정적이다.
