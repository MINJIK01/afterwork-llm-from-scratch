## 1. bf16에서 $1 + 2^{-8}$과 $1 + 3\cdot2^{-8}$

fp32 가수는 23비트이므로 $2^{-k}$는 비트 $23 - k$에 해당한다. $1.0$ = `0x3F800000`.

**$1 + 2^{-8}$** = `0x3F808000` (비트 15).
- 비트 16 = `(0x3F808000 >> 16) & 1` = `0x3F80 & 1` = 0 → 더할 값 `0x7FFF`
- `0x3F808000 + 0x7FFF = 0x3F80FFFF` → 하위 16비트 제거 → `0x3F800000` = **1.0**
- 정확히 중간값이고 결과 최하위 비트가 짝수(0)인 쪽으로 내림.

**$1 + 3\cdot2^{-8}$** = $1 + 2^{-7} + 2^{-8}$ = `0x3F818000` (비트 16, 15).
- 비트 16 = `0x3F81 & 1` = 1 → 더할 값 `0x8000`
- `0x3F818000 + 0x8000 = 0x3F820000` → `0x3F820000` = $1 + 2^{-6}$ = **1.015625**
- 정확히 중간값이고 $1 + 2^{-7}$(가수 홀수)과 $1 + 2^{-6}$(가수 짝수) 중 짝수 쪽으로 올림.

(`bf16_round`로 실행해 `[1.0, 1.015625]` 확인.)

## 2. m5 프리셋 학습 메모리

- 파라미터 + gradient + Adam $m, v$: $12{,}194{,}688\times16$ B $\approx 195$ MB $= 186$ MiB.
- attention 확률 행렬 하나: $B\cdot H\cdot T^2\cdot4 = 32\times6\times256^2\times4$ B $= 48$ MiB/레이어.

이 레포의 attention은 score, max를 뺀 값, exp, 정규화 결과 등 $T^2$ 크기 중간값을 여러 개 저장하므로 레이어당 실제 저장량은 그 몇 배이고, 6레이어면 attention activation만으로 수백 MiB~1 GiB 수준이 된다. 여기에 MLP·norm activation이 더해진다. 이 규모에서도 activation이 파라미터·optimizer 메모리보다 크다. 배치나 문맥을 키우면 그 차이가 더 벌어지며, checkpointing과 FlashAttention(step 21)이 줄이는 대상이 바로 이 부분이다.

## 3. 모든 블록 checkpoint 시 FLOPs 증가와 처리량

backward 중 forward를 한 번 더 계산하므로 학습 FLOPs가 토큰당 $6N \to 8N$, 약 **33%** 증가한다(attention 항 포함 시 비슷한 비율).

같은 메모리로 배치를 2배 키울 수 있을 때:
- 하드웨어가 이미 연산 포화(compute-bound) 상태이면 시간당 처리 토큰은 약 $1/1.33 \approx 0.75$배로 **줄어든다**. 배치가 커져도 FLOPs/토큰은 그대로이기 때문이다.
- 원래 배치가 너무 작아 하드웨어를 덜 쓰고 있었다면 배치 증가로 활용도가 올라가 손실을 상쇄하거나 이득이 날 수 있다.

checkpointing의 주된 가치는 처리량이 아니라 **메모리에 안 들어가던 설정(더 큰 모델·배치·문맥)을 가능하게 하는 것**이다. 재계산 비용을 줄이려면 비용이 싼 연산만 재계산하는 selective recomputation을 쓴다.
