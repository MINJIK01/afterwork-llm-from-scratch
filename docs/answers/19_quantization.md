## 1. m5 블록 가중치를 int4/$G$=32(fp32 scale)로 저장할 때

블록 Linear 가중치: 레이어당 $4d^2 + 3dh = 589{,}824 + 1{,}179{,}648 = 1{,}769{,}472$, 6레이어 합 $10{,}616{,}832$개.

- fp32: $\times4$ B $= 42{,}467{,}328$ B $= 40.5$ MiB
- int4/g32, fp32 scale: 가중치당 $4 + 32/32 = 5$비트 → $10{,}616{,}832\times5/8 = 6{,}635{,}520$ B $\approx 6.33$ MiB

압축비 $32/5 = 6.4$배. scale을 fp16으로 두면 가중치당 4.5비트, 7.1배가 된다. RMSNorm gain(1차원)은 무시할 만큼 작다. 임베딩(1.57M개, 6 MiB)을 fp32로 남기면 모델 전체 압축비는 이보다 낮아진다.

## 2. 비대칭($z \ne 0$) 양자화가 유리한 경우

값의 분포가 0을 중심으로 대칭이 아닐 때이다. 대표적으로 ReLU/SiLU 이후의 activation은 대부분 0 이상이라, 대칭 양자화는 음수 쪽 절반의 정수 레벨을 낭비한다(실효 비트 1 감소). 비대칭은 $[\min, \max]$를 정수 범위 전체에 맞춘다: $s = (\max - \min)/(2^b - 1)$, $z = \mathrm{round}(-\min/s)$. 가중치는 대체로 0 중심 대칭이라 대칭으로 충분하지만, 그룹 크기가 작아 그룹 내 분포가 한쪽으로 치우칠 때는 비대칭이 오차를 줄인다(GPTQ/AWQ의 int4 구현은 흔히 zero-point를 쓴다).

## 3. RTN이 출력 오차를 최소화하지 못하는 이유와 GPTQ의 목적함수

RTN은 각 가중치의 오차 $|w - \hat w|$를 **독립적으로** 최소화한다. 실제로 중요한 것은 출력 오차 $\|WX - \hat WX\|_F^2$인데, 입력 특성들이 상관되어 있으면(공분산 $XX^\top$이 대각이 아님) 가중치 오차들이 출력에서 서로 더해지거나 상쇄된다. 한 가중치의 반올림 오차를 같은 행의 다른 가중치를 조정해 보상할 수 있지만, RTN은 이를 활용하지 못한다.

GPTQ는 행별로

$$\min_{\hat w}\;(w - \hat w)H(w - \hat w)^\top,\qquad H = 2XX^\top$$

를 푼다(OBS/OBQ 계열). 열을 하나씩 양자화하고, 그 오차를 남은 열에 다음처럼 보상한다.

$$\delta = -\frac{w_q - \mathrm{quant}(w_q)}{[H^{-1}]_{qq}}\,(H^{-1})_{:,q}.$$

Cholesky 분해와 열 블록 단위 처리로 수십억 파라미터 모델도 수 시간 안에 양자화한다. 보정에는 소량의 calibration 데이터로 계산한 $H$가 필요하다.
